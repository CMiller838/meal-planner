# Phase 57: Measured nutrient levels for new ingredients (CoFID) [M]

Plain: An ingredient the app doesn't know yet gets its low/med/high nutrient levels worked out from measured CoFID values by a fixed rule, so it stops saying "not tracked yet" and nobody types the levels in.

Requires Phase 50 (built: the "not tracked yet" badge, `untracked()` in `app.js`) and Phase 33b (done: `cofid.json`, `tools/cofid_build.py`, `tools/cofid-map.json`).

## Decisions
- **Own call: the rule is a share of the daily target per 100 g**, thresholds in data: new `tools/cofid-levels.json`
  `{ "high": 20, "med": 10, "low": 5 }` (percent). Targets come from `nutrition-targets.json`, never inlined. Caps
  (`saturates_g_cap`, `sodium_mg_cap`) are used as the denominator for saturates/sodium. No threshold for energy; omega3
  has no CoFID column so it is never derived.
- **Own call: a human picks the CoFID food code, the rule picks the levels.** Mapping an ingredient to a CoFID food is a
  judgment call, so it stays a reviewed edit to `tools/cofid-map.json` (as in 33b), helped by a search command. The
  assistant never writes levels or codes.
- **Own call: only ingredients missing from `ingredient-nutrient-tags.json` are written.** The existing 33 are never
  overwritten; they are compared and the differences listed for the user (their tags are serving-sized judgments, so many
  will differ; that is expected, not a bug). `ingredient-nutrient-tags.json` stays the single source the app and Worker read.
- **Own call: use the `default` (raw/as-bought) food only**; `cooked` entries stay for Phase 33b products.
- No app, Worker or generator code changes: they already read the tags file. No `window`→`root` shim question.

## Signatures
- `cofid_derive.py untracked`: ingredient keys used in `meals.json` (`ingredients[].key`) and absent from the tags file, marking which already have a map entry.
- `cofid_derive.py find <xlsx> <text>`: prints matching CoFID `code  name` rows (reuse `read()` from `cofid_build.py` via import) so the user can choose a code.
- `cofid_derive.py levels <key>`: from `cofid.json` foods + targets + thresholds, prints `{nutrient: low|med|high}` (only nutrients at or above `low`). Pure fn `derive(nutrients, targets, thresholds) -> dict`.
- `cofid_derive.py apply`: for every map key that is not in the tags file and has data in `cofid.json`, add its derived entry to the tags file (sorted insert, `_note` kept). Exits 1 if a mapped key has no `cofid.json` food (run `cofid_build.py` first).
- `cofid_derive.py diff`: for the 28 keys in both files, print `key nutrient: tags=X derived=Y` for every disagreement (including nutrients present on one side only). Read-only.
- Tag nutrient names map to CoFID keys: protein→protein_g, carbohydrate, fat, saturates, fibre, vitA, vitC, vitD, vitB12, folate (`_mcg`/`_mg` as in `cofid_build.py` SHEETS), calcium, iron, zinc, magnesium, potassium, sodium.

## Edge cases
- Nutrient absent from a CoFID food = unknown, never 0 (a `Tr` is 0 already in `cofid.json`): absent means no tag, not "low".
- Ingredient with a map entry but not yet built into `cofid.json`: `apply` fails loudly, writes nothing.
- Ingredient with no map entry: stays "not tracked yet" (correct); `untracked` lists it as "needs a code".
- Key already in the tags file: `apply` skips it; hand-curated tags always win.
- `apply` run twice is a no-op.
